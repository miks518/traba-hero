# Gotchas

Traps that have each cost real time. Most are silent — they produce a passing test, a
plausible number, or an empty result rather than an error.

---

## Toolchain

- `wxt prepare` runs on `postinstall` — generates `.wxt/` with tsconfig and types.
- `.wxt/` and `.output/` are gitignored — **never commit them.**
- `WXT_API_BASE` is a build-time variable — **restart `npm run dev` after changing `.env`.**
- Backend prompt files are in `backend/` root, **not** the project root.
- OpenRouter model IDs have no `~` prefix — the `~` in the UI copy snippet is decorative.
- `tsconfig.json` extends `.wxt/tsconfig.json` (auto-generated by `wxt prepare`).

---

## Shell and mutation testing

- **`Select-String -Path "dir\**\*.py"` does not recurse in PowerShell and silently
  reports nothing found.** It once produced a false "this field is never populated"
  conclusion. **Grep or read the file before concluding a symbol is unwired.**
- **A `Set-Content` round-trip can normalise an em dash to a hyphen**, which turns a
  mutation into a silent no-op. Print whether the substitution actually changed the file
  before trusting the result.
- **Mutation-check a change in both directions.** A test that still passes after a
  deliberate break of the production code was testing nothing. Check the *overcorrection*
  too: `order-last` and `order-3` both "keep the action bar at the bottom", and only one is
  right.
- **Throwaway probe scripts under `ai_verified` were deleted after use** — the cases they
  covered belong in the suite, not in scratch files.

---

## Frontend testing

- **`happy-dom` performs no flex layout and zeroes every `getBoundingClientRect()`.**
  Visual position, FLIP animation, and ring glow cannot be asserted in a unit test;
  **assert the class or order value that produces the effect instead**, and say so in the
  test's docstring.
- **`@testing-library/user-event` is not installed** — use `fireEvent`, as the existing
  tests do.
- Dark mode is toggled via `document.documentElement.classList.toggle('dark')` — Tailwind
  uses `darkMode: 'class'`.

---

## Backend testing

- `python -m pytest tests/ -v` is fully offline and should stay under a few seconds. **If
  it suddenly takes tens of seconds, a test has started reaching the network.**
- **A plain list as a mock's `side_effect` hangs an async test rather than failing it.**
  `unittest.mock` raises `StopIteration` when an iterable `side_effect` is exhausted, and
  CPython cannot raise into an already-running asyncio Future — so the coroutine never
  resumes, the await never returns, and the suite *hangs* instead of reporting a failure.
  Any awaitable mock in `backend/tests/` needs `side_effect` to be a **function**, or the
  list must be long enough for every call the test can make. This is latent in the repo and
  cost real time to diagnose: nothing times out, nothing prints, pytest simply stops.
- **A test that constructs `Settings()` directly bypasses the offline fixture and reads
  the real `backend/.env`.** A failing assertion then prints the whole settings object —
  including the live `AI_API_KEY` — into the test output. Construct settings explicitly, or
  assert on `mod.settings` with monkeypatch, and **never let a secret reach an assertion
  message.**
- **`_env_file=None` is not a pydantic-settings keyword.** Passing it as a kwarg is
  silently ignored and the real `.env` is still read. Write a temp file and point
  `_env_file` at it — and note that even a correct `_env_file` skips only the file, since
  pydantic-settings still lets a real OS environment variable override the class default.
  This is why `class_settings()` exists rather than the kwarg.
- **The rate limiter's memory storage is process-wide, so tests share one budget.** It
  keys on the client address, which is the same `testclient` for every request, and
  `test_verify.py` alone made 16 calls to an endpoint limited to 10/minute — so tests
  passed or failed depending on how many earlier tests happened to run first, and adding
  one endpoint test turned that into a 429 in an unrelated test.
  `_reset_rate_limiter` in `conftest.py` gives each test its own window. `test_rate_limit.py`
  still passes because it asserts the limit *within* a single test. **If endpoint tests are
  added, do not work around a 429 by deleting that fixture.**

## Data semantics

- **A claim nobody could confirm is `yellow`, not `red`.** Absence of evidence is not
  evidence of absence, and it is the rule that keeps small employers from being scored as
  suspicious. A sole proprietorship with no website, no listing and no reviews is the
  ordinary case in the Philippines and is the population this product exists for — the
  traded cost is recorded in `docs/decisions/search-retrieval.md`.
  Points require a retrieved source that **contradicts** the claim.
  A *channel mismatch* is the exception worth noticing: it is a contradiction, not a
  silence, because the employer's own domain exists and the posting directs applicants
  elsewhere. It is also **the only check that can detect an impersonation**, since a real
  employer passes every existence, registration and branch check.
- **One search query per credit, and credits are per request.** A verification issues one
  employer query plus at most two the scan model proposed, so the cap is 3 and a scan that
  proposed nothing still costs 1. The cap is enforced in `verification_flow`, not only in
  the parser: a client that is not this extension can post a longer list.
- **A model that proposes no search verifies on one query, and nothing reports the
  shortfall.** `search_ok` is still true, `search_partial` is still false, and the panel
  reads as a completed lookup. `test_one_search_is_made_when_the_model_proposed_none` pins
  the floor so it is a known number rather than a surprise.
- **`extract_company_name()` runs every pattern over the text as zero-width lookaheads**
  and trims each capture at the first clause boundary, so "Acme Corp. We are hiring" does
  not become a company name. **Evaluate new patterns against that rule** — a greedy capture
  that runs into the next sentence produces a name the search cannot resolve, which then
  looks like an unverifiable company.
- **`source_query` on the frontend `VerificationItem` is always `undefined`.** It is
  declared in `entrypoints/sidepanel/types/index.ts` so a check that arrives with one is typed rather
  than read off `unknown`, but **no backend field emits it.** Do not render it, and do not
  "fix" the backend to emit it — when it is wired up it must be shown as *what was
  searched*, never as evidence about the employer.
- **A shared NAT address will 429 on `/health`.** The limit is per IP and the panel polls
  it continuously, so two or more open panels behind one address exceed it. Fine for one
  user. Raise the limit or back off to 6s if seen.
- **The SEC client was deleted; nothing calls it.** Any test or doc claiming an SEC
  integration is describing something that no longer exists — Tavily is the only retrieval
  path.
